# Спека проекта: генератор тем для Эгеи

## 1. Цель проекта

Selecta — браузерный конструктор тем для блогового движка Эгея. Эта спецификация описывает текущий продуктовый объём; состояние итераций и принятых проверок ведётся в `.project/PROGRESS.md`, будущие идеи — в `.project/IDEAS.md`.

Пользователь открывает страницу, настраивает внешний вид темы в визуальном интерфейсе, сразу видит результат на полноценном превью блога, а затем скачивает готовую папку темы, которую можно загрузить на хостинг и выбрать в настройках Эгеи.

Главная идея проекта:
**дать человеку возможность сделать аккуратную собственную тему для Эгеи без ручного редактирования CSS и PHP-файлов.**

Приоритет проекта — надёжный путь:
**открыл → настроил → скачал → установил → получил ровно то, что видел в превью.**

## 2. Общая концепция

Эгея уже поддерживает наследование тем.

Базовая тема `plain` содержит основную разметку, стили, типографику и поведение. Остальные обычные темы в основном наследуются от неё и переопределяют CSS-переменные, а также метаданные в `theme-info.php`.

Поэтому конструктор генерирует не полностью самостоятельную тему, а **дочернюю тему на основе `plain`**.

Генератор должен работать с единой моделью настроек темы. Из одного и того же состояния должны строиться:

- визуальное превью в браузере;
- файл `styles/main.css`;
- файл `theme-info.php`;
- итоговый архив для скачивания.

Важно, чтобы превью и скачиваемая тема не расходились.

## 3. Основной пользовательский сценарий

1. Пользователь открывает генератор.
2. Видит превью блога в стиле Эгеи.
3. Меняет цвета, шрифты и несколько типографических параметров.
4. Сразу видит изменения в превью.
5. Вводит название темы.
6. Нажимает кнопку скачивания.
7. Получает архив с папкой темы.
8. Загружает папку в каталог пользовательских тем Эгеи.
9. Выбирает тему в настройках движка.
10. Видит на своём блоге тот же внешний вид, который был в генераторе.

Этот путь должен быть коротким и очевидным. Пользователь не должен понимать внутреннее устройство Эгеи, чтобы получить рабочую тему.

## 4. Что именно генерирует проект

Генератор создаёт архив с такой структурой:

```text
theme-name/
  theme-info.php
  styles/
    main.css
```

Где:

- `theme-info.php` описывает тему для Эгеи;
- `styles/main.css` содержит переопределения CSS-переменных поверх `plain`.

Тема должна:

- иметь `based_on` = `plain`;
- иметь корректное имя для отображения;
- содержать цвета для списка тем в настройках Эгеи;
- работать без собственных шаблонов, JS, изображений и встроенных файлов шрифтов; выбранные Google Fonts подключаются через внешний CSS API;
- использовать всё необходимое от родительской темы `plain`.

## 5. Базовые ограничения

В текущем продукте:

1. Генерируются только темы, наследуемые от `plain`.
2. Пользователь получает ZIP-архив с папкой темы внутри, а не отдельные файлы по одному.
3. Генератор работает как отдельный статический веб-проект без связи с конкретной установкой Эгеи.

Эти ограничения сохраняют фокус на визуальной настройке дочерних тем и установке готового архива.

## 6. Возможности конструктора

### 6.1. Живое превью

На странице должно быть полноценное превью блога, достаточное для проверки темы.

Минимально в превью нужны:

- заголовок блога;
- подзаголовок;
- основное меню;
- заголовок заметки;
- основной текст заметки;
- лид;
- обычные ссылки;
- посещённые ссылки;
- тег или вторичная ссылка;
- заметный hover-state;
- цитата или выделенный фрагмент;
- форма или хотя бы поля ввода;
- footer.

Превью должно показывать не абстрактные цветовые квадраты, а именно типичный блог Эгеи.

### 6.2. Настройка темы

Пользователь может настроить:

#### Основные цвета

- фон;
- основной текст;
- заголовки;
- ссылки;
- посещённые ссылки;
- hover;
- вторичный текст;
- теги и служебный текст;
- активные акценты;
- выделенный текст;
- фон и текст полей ввода.

Светлая и тёмная палитры редактируются отдельно.

#### Типографику

- шрифт интерфейса;
- шрифт основного текста заметок;
- размер основного текста;
- масштаб заголовков;
- межстрочный интервал основного текста.

#### Несколько общих параметров композиции

- максимальную ширину контента;
- ширину боковых отступов.

Не нужно выводить все переменные `plain`. Нужно дать только те настройки, которые человек действительно понимает и которые заметно меняют характер темы.

### 6.3. Название темы

Пользователь должен ввести:

- техническое имя папки темы;
- отображаемое имя темы.

Техническое имя автоматически предлагается из отображаемого; пользователь может его поправить.

### 6.4. Скачать тему

Пользователь должен получить готовый архив по одной кнопке.

Архив должен содержать папку темы, а не просто россыпь файлов в корне архива.

Имя архива должно быть понятным, например:

```text
my-theme.zip
```

### 6.5. Проверка перед скачиванием

Перед генерацией архива нужно проверить как минимум:

- заполнено ли отображаемое имя;
- задано ли допустимое имя папки;
- нет ли недопустимых символов в имени папки;
- есть ли минимально необходимые значения;
- допустимы ли значения цветов, шрифтов и числовых параметров;
- задан ли единственный поддерживаемый родитель `plain`;
- согласованы ли цвета в `theme-info.php` с тем, что реально используется в CSS.

Если проверка не проходит, пользователь должен получить понятное объяснение, что нужно исправить. Данные из JSON, URL и локального хранилища проходят общую проверку формы и допустимых значений; недопустимый CSS и нечисловые или выходящие за пределы контролов значения не применяются.

### 6.6. Готовые варианты и продолжение работы

- Пресеты воспроизводят встроенные темы Эгеи, включая их поддержку тёмной палитры, но результат всегда наследуется от `plain`. Пресеты показаны сеткой карточек: локализованное название и полоска из цветов основной палитры в порядке слева направо: фон, текст, заголовки, ссылки, при наведении. Выбор выделяется; при собственных изменениях без совпадения с пресетом показывается «Своя тема».
- Random предлагает новый набор настроек. Блокировки отдельных полей и групп сохраняют выбранные значения при Random; для светлой и тёмной палитр блокировки отдельные.
- Неблокирующие предупреждения о контрасте помогают оценить текущую палитру.
- Настройки можно экспортировать в JSON, импортировать из JSON и передать ссылкой с состоянием темы в URL.
- Текущая сессия сохраняется локально: тема, блокировки и состояние интерфейса. Нетронутая вкладка не должна перезаписывать более новую сохранённую сессию другой вкладки.
- Новый импорт, редактирование темы или блокировок, Reset и закрытие компонента отменяют применение результата предыдущего незавершённого чтения JSON-файла, папки темы или ZIP.
- Интерфейс и демо-контент доступны на русском и английском языках.

## 7. Модель темы

В проекте должна быть явная модель состояния темы.

Примерно по смыслу она должна содержать:

```text
meta
  folderName
  displayName
  basedOn
  supportsDarkMode
  useLikelyLight

palette / darkPalette
  background
  foreground
  headings
  link
  linkVisited
  hover
  tag
  engineText
  admin
  active
  markedTextBackground
  inputBackground
  inputText

typography
  mainFontSource
  mainFontFamily
  noteFontSource
  noteFontFamily
  noteTextSize
  noteTextLineHeight
  titleScale

layout
  maxWidth
  margins
```

Не обязательно именно с такими именами в коде, но смысловые группы должны существовать.

Из этой модели должны строиться:

- CSS-переменные;
- значения `colors` в `theme-info.php`;
- превью;
- сериализуемое состояние для JSON и ссылок с настройками.

Язык, внешний вид оболочки, размеры панелей и блокировки относятся к состоянию приложения, а не к экспортируемой теме. Они не включаются в JSON темы, ссылку и ZIP.

## 8. Принцип генерации CSS

Генерируемый `styles/main.css` не должен дублировать всю тему `plain`.

Он должен содержать только осмысленные переопределения поверх родителя.

Примерная структура:

```css
:root {
  --backgroundColor: ...;
  --foregroundColor: ...;
  --headingsColor: ...;
  --linkColor: ...;
  ...
}
```

Если какие-то значения являются производными от основных цветов, генератор должен сам вычислять их и записывать в CSS.

Например:

- прозрачный фон;
- underline-цвета;
- thin rule;
- размер и межстрочный интервал заголовка заметки.

Для Google Fonts CSS начинается с `@import` выбранных семейств. При включённой поддержке тёмного режима за базовым `:root` следует блок `@media (prefers-color-scheme: dark)` с селектором `:root .e2-responds-to-dark-mode`.

Пользователь должен задавать понятные исходные значения, а не ручками собирать десятки технических переменных.

## 9. Принцип генерации `theme-info.php`

Файл должен содержать как минимум:

- `display_name`;
- `colors`;
- `based_on` = `plain`;
- `meta_viewport`;
- `supports_dark_mode`.

Для темы используется одно отображаемое имя без локализаций. Русский и английский языки интерфейса конструктора не меняют метаданные экспортируемой темы.

Поле `colors` отражает основные цвета светлой палитры, как в проверенном контракте Эгеи:

- background;
- headings;
- text;
- link.

Важно: `theme-info.php` не должен становиться вторым источником истины. Он должен генерироваться из той же модели, что и CSS.

## 10. Превью и установка

Генератор должен давать пользователю уверенность, что скачанная тема поведёт себя так же, как превью.

Для этого нужно:

- использовать в превью ту же структуру переменных, что и в реальной теме;
- не рисовать отдельный “макет ради макета”, который не похож на Эгею;
- показывать состояния, на которых тема чаще всего ломается:
  - ссылки;
  - вторичный текст;
  - формы;
  - длинные заголовки;
  - светлую и тёмную палитры при включённой поддержке тёмного режима.

Превью использует статический демо-контент на основе английского и русского превью тем Эгеи с дополнительными состояниями для настройки темы. Целевая версия — Эгея `11.5`, сборка `v4199`; точный commit, объём переноса и maintenance checklist зафиксированы в `PREVIEW-BASELINE.md`. Более новая ветка Эгеи не меняет целевой контракт автоматически.

## 11. Экспорт

Проект работает без backend.

Сценарий экспорта:

- все файлы генерируются в браузере;
- архив собирается на стороне клиента;
- скачивание начинается по нажатию кнопки;
- проект можно разместить на статическом хостинге.

Экспорт должен выдавать:

```text
theme-name.zip
└── theme-name/
    ├── theme-info.php
    ├── selecta.json
    └── styles/
        └── main.css
```

JSON-настройки экспортируются отдельно в `<folderName>.selecta.json`, а также входят в папку темы как `selecta.json`.

### 11.1. Импорт папки темы и ZIP

- Кнопка «Импорт темы» сразу открывает системный выбор файлов, без промежуточного меню. Принимается один ZIP, один JSON либо CSS и/или PHP с необязательным JSON. Можно выбрать CSS и PHP вместе; несколько файлов одного типа и ZIP вместе с другими файлами отклоняются. Для отдельных файлов имя папки сохраняется из JSON или берётся из значений по умолчанию.
- Папку темы или файлы можно перетащить на кнопку. При наведении с файлами кнопка подсвечивается. Одна папка импортируется целиком в рамках поддерживаемых настроек; несколько папок или папка вместе с отдельными файлами отклоняются. Чтение перетащенной папки защищено от устаревших результатов и ошибок с самого события drop.
- Можно также импортировать ZIP: одна тема непосредственно в корне архива или в одной папке верхнего уровня. Для архива без папки техническое имя берётся из имени ZIP. Несколько тем в одном архиве не выбираются автоматически. ZIP разбирается в памяти; на диск ничего не распаковывается. Правила приоритета и поддерживаемых данных те же, что для папки.
- Для ZIP читаются только три поддерживаемых файла. Пределы: архив до 32 МиБ, каждый читаемый файл до 1 МиБ, до 4096 записей в архиве. Неоднозначные архивы, дубликаты файлов темы и неподдерживаемое сжатие выбранных файлов отклоняются; прочие файлы не распаковываются.
- Пользователь перетаскивает непосредственно папку темы. Читаются только `selecta.json`, `theme-info.php` и `styles/main.css` в этой папке; вложенные темы и остальные файлы не импортируются.
- Валидный JSON служит исходным состоянием, иначе используются значения Selecta по умолчанию. Отсутствие или повреждение JSON не мешает импорту PHP/CSS. Папка должна содержать хотя бы `theme-info.php` или `styles/main.css` с распознаваемыми данными темы.
- Поддерживаемые значения из PHP и CSS всегда перекрывают JSON. Метаданные берутся из PHP; имя папки — из выбранной папки с нормализацией. Для цветов CSS имеет приоритет над `colors` из PHP.
- PHP читается как статический массив данных: отображаемое имя, флаги поддержки тёмного режима и светлых кнопок, четыре цвета метаданных. Выражения и исполняемый код не выполняются. Результат всегда наследует `plain`, другие цепочки наследования не восстанавливаются.
- CSS читается как данные: известные переменные палитры, шрифтов, размеров и полей в `:root`, а также тёмная палитра в экспортируемом блоке `prefers-color-scheme: dark`. При повторении учитываются порядок и `!important` в поддерживаемой области.
- Применяются только значения, представимые текущей моделью и допустимые для её контролов. Неподдерживаемые селекторы, выражения, единицы, асимметричные поля и прочие правила пропускаются. Ни чужой CSS, ни PHP не вставляются и не выполняются в приложении; внешние импорты CSS не загружаются.
- Отсутствующие или неподдерживаемые значения сохраняют JSON/defaults. Удалённые из CSS переопределения шрифтов возвращаются к наследованию `plain`; отключённая тёмная палитра может сохраняться в JSON. Отсутствующий в статическом PHP флаг `use_likely_light` означает `false`, как в экспортируемой теме на базе `plain`.
- Импорт применяется целиком после чтения и проверки, снимает блокировки и сохраняется как обычный импорт. Новый импорт, правка темы, Reset или закрытие компонента отменяют применение устаревшего результата и его ошибок.
- Экспорт создаёт новую тему из поддерживаемых настроек. Произвольные шаблоны, стили, изображения и другие файлы исходной папки не копируются. Это частичный перенос настроек, не редактор произвольной темы Эгеи.

## 12. Интерфейс

Интерфейс должен быть рабочим инструментом, а не лендингом.

Основной экран:

- слева панель настроек;
- справа большое превью;
- вверху левой панели закреплены название генератора и кнопка настроек интерфейса; поповер содержит оформление оболочки и язык;
- середина левой панели прокручивается: Random, Reset, пресет, единая кнопка импорта темы (папка или файлы JSON/ZIP/CSS/PHP), метаданные и группы контролов;
- внизу левой панели закреплены основная кнопка скачивания ZIP и меню дополнительных действий: скопировать ссылку и скачать JSON;
- переключатель светлой/тёмной темы находится сверху справа внутри области превью и остаётся доступным при его прокрутке; под него отведено место, чтобы не перекрывать содержимое блога;
- заголовок раздела цветов показывает редактируемую светлую или тёмную палитру.

Ширину панели настроек можно менять. Режим темы управляет редактируемой палитрой и превью; вид интерфейса управляет только оболочкой конструктора.

При ширине окна до `43rem` панель и превью идут друг под другом на всю ширину. Подписи узких полей располагаются над контролами, а замочки остаются справа от них. ZIP и меню экспорта закреплены внизу экрана с учётом безопасной зоны устройства; в конце страницы зарезервировано место под них и сообщения валидации.

Контролы должны соответствовать типу данных:

- color picker для цветов;
- select для набора шрифтов;
- slider или stepper для размеров;
- radio group для светлого и тёмного режимов;
- switch и checkbox для бинарных параметров и блокировок.

Не нужно превращать интерфейс в иллюстративный маркетинговый сайт. Он должен быть спокойным, плотным и удобным для многократных проб.

Основной сценарий использования генератора — десктоп. На узких экранах интерфейс и превью должны сохранять аккуратный вид без наложений и сломанной вёрстки; отдельная мобильная версия и расширенная проверка при zoom 200% не требуются. Отдельный переключатель мобильного превью не нужен: пользователь при необходимости может сузить окно браузера.

## 13. Шрифты

Пользователь выбирает источник шрифта отдельно для интерфейса блога и основного текста заметок:

- наследование от `plain` без переопределения семейства в экспортируемом CSS;
- системные стеки и именованные системные гарнитуры;
- Google Fonts из фиксированной подборки с кириллицей.

Выбор остаётся в одном сгруппированном select. Отдельный каталог с поиском Google Fonts не входит в текущий объём.

Google Fonts загружаются через CSS API в превью и через `@import` в экспортируемой теме. Подключаются только выбранные семейства без дубликатов, с доступными начертаниями и `display=swap`. Для каждого семейства предусмотрен системный fallback; внешний шрифт зависит от доступности сети и сервиса Google. Файлы шрифтов не включаются в ZIP.

Шрифт кода наследуется от Эгеи `plain` и отдельно не настраивается.

## 14. Тёмная тема

Тема хранит светлую и тёмную палитры отдельно. Метаданные `supports_dark_mode` отражают поддержку тёмного режима; переключение превью в тёмный режим включает эту поддержку.

Светлая палитра экспортируется в базовый `:root`. Тёмная — только при включённой поддержке, в реальный контракт Эгеи: `@media (prefers-color-scheme: dark) { :root .e2-responds-to-dark-mode { ... } }`. В живом блоге применение зависит также от настройки Эгеи реагировать на тёмный режим.

Превью эмулирует выбранную палитру локально. Оболочка Selecta имеет независимый светлый или тёмный вид; первый выбор определяется системной настройкой, затем хранится конкретное значение. Вид оболочки не влияет на экспортируемую тему.

## 15. Валидация качества темы

Конструктор показывает неблокирующие предупреждения о контрасте для редактируемой палитры. Они помогают оценить читаемость текста, ссылок, вторичных элементов и полей ввода, но не запрещают скачивание и не гарантируют доступность всех сочетаний и состояний блога.

Проверка корректности данных и имени папки перед экспортом остаётся обязательной и отделена от предупреждений о качестве палитры.

## 16. Архитектурные требования

Проект должен быть устроен так, чтобы UI и генерация файлов не были смешаны.

Использовать:

- Vite;
- Vue;
- JavaScript без TypeScript;
- `vue-i18n` для русского и английского интерфейса;
- локальные Vue-адаптеры над `hvab-blocks` 0.3 для оболочки;
- `reka-ui` для поведения меню, диалогов и подсказок;
- `fflate` для ZIP в браузере.

Разделение оболочки и превью описано в `UI-ARCHITECTURE.md`. Стили и токены `hvab-blocks` не должны менять редактируемую тему Эгеи.

По смыслу нужны отдельные части:

- модель темы;
- вычисление производных значений;
- генерация CSS;
- генерация `theme-info.php`;
- сборка архива;
- демо-контент для превью;
- UI-слой;
- валидаторы.

Важно, чтобы:

- состояние темы было сериализуемым;
- генераторы файлов можно было тестировать отдельно от UI;
- превью брало значения из той же модели, что и экспорт;
- добавление новых контролов не требовало переписывать весь проект.

Превью должно строиться на зафиксированной версии реальной разметки и контракта CSS-переменных Эгеи. В проекте нужно явно хранить, с какой версией Эгеи это превью сверено, и поддерживать короткий maintenance checklist на случай обновления движка:

- проверить список CSS-переменных `plain`;
- проверить значимые куски layout-разметки;
- проверить, не появились ли новые состояния, которые нужно показать в превью;
- при необходимости обновить эталонную разметку и список переменных.

## 17. Что не входит в текущий объём

Не добавлять без отдельной задачи:

- редактор произвольного CSS;
- редактор PHP-шаблонов;
- полное восстановление произвольных тем и их исходных файлов;
- поддержку не-`plain` баз;
- публикацию тем в общую галерею;
- аккаунты;
- backend;
- хранение пользовательских тем на сервере;
- полноценный каталог Google Fonts;
- кастомные изображения, логотипы и иконки;
- конструктор layout-шаблонов;
- visual diff между темами;
- автоматическую установку темы в живую Эгею;
- сложную систему пресетов с маркетинговыми названиями;
- встроенные файлы шрифтов.

Основной сценарий остаётся прежним: человек без ручного кода может собрать и установить рабочую тему.

## 19. Принятые решения и границы проверки

Демо-контент и порядок сопровождения превью определены в `PREVIEW-BASELINE.md`. Установка экспортированной темы в Эгею и работа превью приняты пользователем; обязательный аудит закрыт. Объём выполненных проверок и оставшиеся необязательные наблюдения хранятся в `.project/PROGRESS.md`.

Приоритет — десктопный сценарий и визуально целая узкая вёрстка. Дальнейшие мобильные и zoom-проверки исключены из плана по решению пользователя. Доступность внешних шрифтов и предупреждения о контрасте не дают гарантии одинакового отображения на всех платформах и во всех состояниях блога.

## 20. Критерии готовности текущего объёма

Текущий объём должен сохранять следующие свойства:

- генератор открывается в браузере;
- пользователь может менять основные цвета темы;
- пользователь может менять хотя бы базовые типографические параметры;
- изменения сразу видны в превью;
- превью достаточно полно показывает типичный блог Эгеи;
- пользователь может задать имя темы;
- по кнопке скачивается ZIP-архив с корректной папкой темы;
- в архиве есть валидные `theme-info.php` и `styles/main.css`;
- тема наследуется от `plain`;
- после загрузки в Эгею тема появляется в списке тем;
- после включения темы блог выглядит в целом так же, как в превью генератора;
- CSS и `theme-info.php` строятся из одного состояния, без ручного рассогласования;
- ошибки в базовых данных показываются пользователю до скачивания;
- светлая и тёмная палитры одинаково используются в превью и экспортируемом CSS;
- пресеты, Random и блокировки работают с общей моделью;
- JSON и URL передают настройки темы без состояния оболочки;
- нетронутая вкладка не перезаписывает более новую сохранённую сессию другой вкладки;
- русский и английский интерфейсы дают доступ к одинаковым возможностям;
- системные и Google-шрифты подключаются согласно выбранному источнику без файлов шрифтов в ZIP.

## 21. Критерий качества

Хороший результат — это не “много ручек”.

Хороший результат такой:

- человек без знания CSS быстро собирает тему, которая выглядит цельно;
- превью честно показывает будущий результат;
- скачанная папка сразу работает в Эгее;
- у темы есть характер, но интерфейс генератора не заставляет разбираться в устройстве движка;
- конструктор остаётся компактным и расширяемым;
- новые возможности добавляются отдельными небольшими итерациями.
